# 小屋 · 两个人的日常

Desktop app ID: `home3d`. Only `home3d.js` loads at startup. It lazily loads the local Three.js r180 MIT bundle, classic-script catalogs and independent modules, so Android's `file:///android_asset` entry also works without import maps, a CDN or `fetch(file:)`.

The first visit lets the user set a reference and bind an existing one-to-one character. Subsequent visits open the original day/night house entrance; 回家 returns to that character's saved room. In-house settings can switch the character; each character keeps a separate home. User appearance is shared, while character appearance, photos, memories, furniture choices and activity are per home. The source of the character reference is `getWechatImageReferenceForChar`, including the chat settings reference before avatar fallback.

Rooms and furniture use real 3D geometry. The silver-haired male and bunny-eared, blue-dress female are packaged locally and used for the character and user respectively when no custom portrait or explicit portrait choice exists. Settings switch each figure independently without deleting portraits or references. The male has a model-specific starter skeleton; the female preserves Tripo's 23-joint Mixamo skin weights and measured anatomy. Both retain PBR materials and independent near/middle/far resources. Blink animation, polished cloth deformation and physical-device performance still need work.

Sleep preserves body volume and uses separate torso/pillow/foot contact heights. Boots are removed to the floor and replaced by the reviewed Tripo barefoot mesh, then restored on standing. Both figures remove the generated trouser cuff. Their ankles fit the measured boot-removal edge of each far/middle/near mesh, with a 25mm overlap inside the retained leg. Sleep uses a model-specific closed-lid material expression; waking restores the original eye texture, including across LOD changes. Crown/ears clear the headboard/sofa arm without compressing the body. Seated legs adapt to support height; walking flexes knees and stabilizes the stance foot. The open reading book follows samples of the actual skinned hands and disappears during walking. These remain a starter rig and locally built props, rather than finished character animation/wardrobe assets.

Transparent Q-version portraits continue to work offline or through explicit image generation. Dedicated portraits use the user's existing image API and reference settings. Generation saves a preview; confirmation switches to the saved portrait. No paid generation starts on entry. Portraits remain 2D sprites/pose surfaces; they must not be described as rigged 3D models.

## Living and construction

生活模式 advances a local activity every 90 seconds (sleep uses longer intervals), with the character walking around furniture and settling into usable positions. Decisions consider time, character personality/status, recent private context, known Living World events, available facilities and local energy. AI only supplies an explicit high-level plan when the user requests it. Offline catch-up is bounded to the last day and labels its journal entries as local simulation; no background network request is needed. Furniture retains last-use and plant-care traces.

装修 opens a bottom furniture catalog. Drag from the catalog, tap a room object to move it, rotate 90 degrees, fine-tune with arrows, then confirm. Keyboard arrows and R work as alternatives to dragging. A fixed tray height keeps floor projection stable during selection. Collision, room bounds and navigable access are checked before an atomic save. Cancel leaves the original layout intact; moving/removing a table or cabinet includes supported props. Existing v1 saves gain sparse per-room overrides without resetting portraits or memories.

The five original series (cream, European, Japanese, modern and Chinese) include 55 procedural variants, with four additional eight-piece series (botanical, rose loft, pink garden and monochrome), plus 12 cream/European additions (sink, fridge, dining table, sideboard, fireplace and wardrobe). The cream/European series and compatible initial furniture use the reference-inspired geometry in `furniture-visuals.js`: framed upholstery, curved wood legs, brass hardware, paneled cabinets, open shelving, layered bedding, pleated lamps and leafy potted plants. Static details are baked into one mesh per material (at most 10 batches and fewer than 10,000 triangles per item). The supplied screenshots and linked packs are visual references; these additions are original local geometry and require no purchase, download or remote texture. Existing saved custom placements remain compatible. Catalog type definitions supply shared interactions and positions; visual variants provide style, dimensions and geometry. Living room, bedroom, game room, kitchen and dining room are available initially; bathroom, balcony, wardrobe, studio and collection remain modular extensions. Each room loads independently.

Private saved home context is available to character chat and the single-actor Living World agent even before the renderer loads. It is not included in the public multi-actor world-generation context. Local relationship settings do not silently rewrite the public relationship graph.

Entrance artwork lives under assets/home3d/entrance; prompts.json records the built-in ImageGen prompts. These are decorative illustrations; actual furnishings remain editable 3D objects. Portrait and 3D character representations share the same navigation/activity/interaction contracts.

## Modules

- `state.js`: durable, atomic localStorage writes; separate character homes; visits, moments and memory keepsakes. Save errors propagate to the UI. `bynd_home3d_v1` participates in BYND's existing backup/import system, including small saved reference and photo images.
- `bridge.js`: existing characters, chat reference, recent history, character phone, visible Living World events, granted reality-life summaries, Memory, album and application navigation. It never reads reality-life records directly or bypasses a character's grant.
- `living.js`: deterministic, time-aware offline activity; optional explicit AI decisions restricted to catalog furniture, open rooms, actions and valid placement slots. The current schedule persists while the user is away, and is recomputed when expired on entry. API errors retain the old plan. No background API spend is required.
- `build.js` / `build-ui.js`: layout validation, sparse saved overrides, support-aware movement, pointer dragging, catalog filters, cancellation, rotation and modular room expansion.
- `furniture-visuals.js`: original procedural geometry for the furniture style series, independent of shared functional type definitions.
- `interiors.js`: seven coordinated room sets (奶油花园, 法式晨光, 森系书房, 玫瑰阁楼, 自然公寓, 粉白花园, 黑白星落), eight wallpaper/wall finishes and eight floor finishes, with matching trim, curtains/shutters, framed botanical prints, rugs and optional trailing greenery. Original 1K procedural surface maps use real world repetition and the existing texture budget/mipmap policy. Complete sets match currently placed furniture without changing footprints or positions; later individual pieces keep their own style. Each room/character saves independently through the atomic state layer, and surface textures are released on room changes.
- `rooms.js`: independently loaded rooms, shells, placement slots and interaction anchors. Room definitions list nine room modules; living room, bedroom and game room are open initially and the other six can be expanded per home. Add future rooms through this catalog rather than extending a monolithic house scene.
- `furniture.js`: self-contained GLB, material normalization, a 3MB LRU byte cache, procedural rounded upholstery/props and photo frames. The file origin uses XHR for local binary assets.
- `materials.js`: reusable fabric, wood, plastic, metal, glass and ceramic presets, with tiny procedural bump maps. Four themes change the palette, lighting and background while retaining geometry.
- `portraits.js`: reference-based image generation, shared pending lock and provider cooldown, transparent-background validation/removal, bounded cropped PNG storage, preview/confirmation and stale-reference/character checks. Errors preserve the current portrait and propagate to the UI. Packaged portrait preparation caches only CPU data; GPU textures belong to each active scene.
- `characters.js` / `animation.js`: camera-facing portrait sprites with seated/lying placement and walking/breathing motion. Activity types and furniture occupancy still govern interactions, phones, games, sleep and hugs; navigation uses a 14cm grid with swept body clearance, exact endpoints and visibility smoothing around actual furniture bounds. Male/female radii are 38cm/52cm, covering measured near-model gait and hair/skirt volume. The old parameter profile parser remains compatible with existing saves.
- `character-models.js`: locally packaged male GLBs, asset-specific starter skinning, furniture-aligned seated/lying poses, projected-size LOD and fast actor picking hull. Optional detail-loading failure retains the current model; stale results release their resources. GLB byte mirrors support ordinary file browsers and Android without embedding any API key.
- `scene.js`: real-time room lifecycle, bounded concurrent model decoding, picking, budgeted shadows/lights/particles and WebGL error recovery. Leaving the app cancels animation and releases room geometry, both LOD levels, textures, materials, shadow targets, timing queries and the GL context. Only bounded CPU GLB bytes remain cached.
- `room-camera.js`: close default composition, damped world-space pan and pinch/wheel zoom, room-bound focus, reset and a separate rotation API. Narrow phones deliberately crop the room instead of fitting its entire floor into the viewport.
- `render-quality.js`: 流畅 / 均衡 / 极致 / 自动, local device preference, bounded actual framebuffer pixels/DPR, capability hints and sustained CPU/GPU/frame-time adaptation. GPU timing is optional and asynchronous.
- `render-assets.js`: shared-texture budgets, 1K/2K furniture and 2K/4K hero ceilings, correct color spaces/mipmaps/anisotropy, and projected-size geometry LOD with hysteresis. Textured GLBs retain their PBR maps; higher quality never upscales a source texture.
- `icons.js` / `ui.js` / `home3d.css`: offline controls, onboarding, settings, room selection, interaction sheets, memory journal and native safe-area handling.

## Asset provenance and rebuilding

All packaged geometry is inventoried in `assets/home3d/asset-manifest.json` with original filename, author, official source, license, commercial/modification permissions, attribution requirements and SHA-256. The supplied FBX subset is recorded as user-provided Quaternius; Kenney's original included license is preserved. Source evidence lives in `assets/home3d/licenses`. Tiny room decorations and avatar meshes are BYND's own procedural geometry.

Initial portrait sources and exact generation prompts are recorded in `assets/home3d/characters/README.md`. The original transparent PNGs are unchanged. `initial-portraits.js` mirrors their bytes as data URLs so ordinary `file://` browsers can upload them to WebGL without opaque-origin image restrictions; it loads only when entering the home.

Preparation uses Three.js `0.180.0` and esbuild `0.25.10` in an external tool directory:

```
npm install --prefix artifacts/home3d-tools --no-audit --no-fund --save-exact three@0.180.0 esbuild@0.25.10
node scripts/prepare-home3d-assets.cjs [tool-directory] [download-directory]
```

Canonical data lives in the three `data/*.json` catalogs. The preparation script generates `data/catalogs.js` as their Android-compatible classic-script mirror; tests enforce equality. When editing a catalog, regenerate this mirror. Do not hand-edit the bundled Three.js engine or exported GLB files.

## Verification

`node tests/run.cjs` covers save failure, invalid imported data, per-character separation, local schedules, AI failures and invalid plans, delayed decisions after switching character, reference parsing, pathfinding, catalog consistency and packaged model licensing/structure.

`node scripts/check-home3d-browser.cjs` exercises actual WebGL rooms, initial portrait sprites, room switches, memory keepsakes, sleep and themes, native 47px top inset at 320/375/430px, explicit generation previews/confirmation, 429 preservation/cooldown, close/reopen locks, and disposal on HTTP and file origins. Image API responses are test stubs; no real user API or user data is used. Screenshots and the report are saved under `artifacts/home3d`.

`node scripts/check-home3d-background-browser.cjs` runs real U2NETP/ONNX inference on an opaque illustration with the public resource mirror blocked. It checks file and HTTP origins, transparent output, retained opaque subject colors, removal of temporary script nodes, and the home preview/confirmation workflow. API output is simulated; local background inference uses the actual packaged model and runtime. Its report is under `artifacts/home3d-background`.

Personalized image generation requires the user's configured provider to support image references. Transparent outputs are preferred; opaque outputs use the existing BYND background-removal module and must pass alpha validation before saving. Android hardware performance is not inferred from desktop screenshots; run a device check before raising quality caps. The current procedural decorations have projected-size LOD. Imported furniture and future rigged characters require authored LOD assets; Draco/KTX2 are not configured. The implemented quality budgets, asset policy and physical-device acceptance plan are documented in [mobile-renderer.md](../../docs/design/home3d/mobile-renderer.md).

`node scripts/check-home3d-build-browser.cjs` verifies pointer dragging, rotation, cancellation, storage failure, deletion, modular expansion, autonomous walking to a piano, day/night entrance, reload persistence, disposal and native top insets at 320/375/390/430px. Evidence is saved under artifacts/home3d-build.

`node scripts/check-home3d-furniture-browser.cjs` renders the new furniture in real mobile living rooms, bedrooms and kitchens, captures cream/European arrangements at 390px and desktop widths, checks geometry budgets, new placement persistence and failed saves, and verifies scene disposal. Fixture screenshots and the report are saved under `artifacts/home3d-furniture`; personalized user homes are never modified. `tests/home3d-furniture.test.cjs` also raycasts actual cushion heights and the recessed sink, validates finite geometry and catalog footprints, and checks offline procedural loading.

`node scripts/check-home3d-interiors-browser.cjs` checks the 装修 → 墙地套装 controls, all seven complete sets, separate finish choices, reload persistence, storage failures, the 320px selector layout, texture budgets and disposal. Actual mobile/desktop screenshots are in `artifacts/home3d-interiors`. Unit tests also cover per-character/room separation, restoring custom finishes to a preset, imported invalid finishes and respecting individually chosen furniture.

`node scripts/check-home3d-renderer-browser.cjs --check` verifies 320–430px phones (640/740/844px tall), DPR 3, parent/header safe-area ownership at 47/59px, unobscured world area, actual drawing-buffer dimensions, touch pan/pinch, short-screen room switching, four quality modes, uploaded PBR texture reallocation, failed preference writes, context-loss recovery and disposal. Reports and screenshots go to `artifacts/home3d-renderer`. Without `--check`, it serves an isolated demo at `http://127.0.0.1:8797/room`; it uses fixture data and makes no paid AI request.

`furniture-previews.js` renders the exact selectable model using a shared orthographic WebGL preview renderer. The compact bottom drawer uses horizontal categories and a scrollable preview shelf; vertical drags place furniture while horizontal touch gestures scroll the shelf. Cached previews are bounded to 48 items and the temporary renderer is disposed on leaving decoration mode.

`node scripts/check-home3d-picker-browser.cjs` verifies actual previews, native horizontal touch scrolling without accidentally selecting furniture, tap/cancel, 320px layout under 47/59px parent/header safe areas and disposal. Its screenshots/report are in `artifacts/home3d-interiors`.

Sleep bedding uses a bed-owned, closed 3D quilt (under 7K triangles). It samples the current skinned torso/legs/feet once when sleepers or character LOD change, leaves faces outside the cover, and returns to a flat drape on waking. Mattress and pillow meshes match their declared contact surfaces. This is a lightweight pose contour, not real-time cloth simulation. Sleep-only trouser hem morphs meet the actual barefoot ankle; awake boots and original outfit geometry restore together.

`node scripts/check-home3d-body-contact-browser.cjs` checks real far/middle/near ankle continuity, short ankle proportions, headboard/pillow contact, closed eyes, body coverage and face exposure by raycasting the actual quilt. Mobile screenshots and measured reports go to `artifacts/home3d-renderer/body-contact-v1`. `tests/home3d-bedding.test.cjs` also verifies closed cloth topology, all bed styles, rotated placement, two sleepers, cached contours, waking and disposal.

Two sleepers on a double bed use `sleep-pair.js` when the existing hug permission is enabled: a cached inward lean, measured head clearance and a two-joint arm reach. Leaving the bed, disabling hugs or switching character LOD rebuilds the appropriate solo/pair pose. No bone length or whole-avatar scale changes are applied. Loose female skirt/back strands use a reversible sleep drape morph with updated cloth normals; face geometry and awake appearance remain unchanged. The shared quilt uses one continuous opening and follows the torso/legs, with exposed arms outside the cover. This remains a pose approximation rather than cloth physics or a professionally authored couple animation.

`node scripts/check-home3d-sleep-pair-browser.cjs` captures covered/uncovered mobile pair views and measures actual quilt coverage, face exposure, mattress/pillow clearance, hand reach and cloth-to-body distance. The isolated demo accepts `?pose=sleep&close=1&together=1` to preview both sleepers.

The local living planner uses time, needs and recent context with fixed phrases (`source: local`); offline catch-up is a labeled simulation. Only the explicit “让 Ta 安排一会儿” request calls the configured chat API. Arrival uses a compact journal notice rather than presenting a long simulated activity as a generated message.

Room-specific defaults keep a bedroom reading corner clear of the double-bed approach; the kitchen has a fridge, stove/pot, recessed sink, prep counter, ingredient island and cup/spice shelf; the dining room has four chairs and place settings. Gaming defaults use a monitor, real keyboard keys, speakers and gamepad, without the generic TV/mirror. The previous faceted keepsake is replaced by an original plush bear. Sofa head and back contacts share measured cushion surfaces. Desk and dining interactions require actual facing chairs, reserve their seat IDs, and reject missing seats; clicking a computer resolves its supporting desk. Existing saved custom furniture is retained, including deliberately added gaming televisions.

Every room shares the catalog's `interiors.defaultPreset` (cream garden: warm white, light wood and sage); future rooms inherit the same default. Only an explicit per-room user selection overrides it. Room functions change furniture layout, not the default decor palette.

`node scripts/check-home3d-room-layouts-browser.cjs` checks actual 3D sofa contacts, monitor direction, two dining seats, cooking/sleep poses, room changes, gaming mirror exclusion and 320px layouts under 47/59px safe areas. Screenshots and reports are in `artifacts/home3d-renderer/room-layouts-v1`. Preview `?room=kitchen`, `?room=dining_room`, `?room=game_room` or `?action=Lie`; these use isolated fixture data.
