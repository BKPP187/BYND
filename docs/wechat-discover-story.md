# 视频号与剧情直播

视频号保留角色／世界 NPC 的作品、关注、收藏、公开评论和回复；一起看是可继续的双人会话，能选场景、发言、结束并把共同经历带回私聊。直播保留房间、弹幕、点歌、当场选择、NPC 发言和收播结果。内容依据角色人设、已启用世界书和本轮剧情，公开内容不得暴露无关私聊。

入口为微信的发现／动态页。视频号顶部为头像式视角入口，选择面板包含“我的视角”和每个角色的视角，并随全部微信主题变化。**谁的视角，就是谁的操作身份。**“我的视角”以 user 身份操作；例如切到商桓的视角后，评论、回复、点赞、关注、收藏、发布、转发与一起看都以商桓身份进行，不能仍署 user 的名字。用户有权访问角色视角不等于角色视角变成用户视角。角色自己的作品不提供关注自己按钮，数据层也拒绝自己关注自己。评论整条为可点击、可键盘操作的回复入口，不再在旁边放独立的“回复”按钮。

我的视角显示各世界作品；角色视角显示该角色与同世界朋友的公开作品，以及分享到该世界的作品。进入角色视角仍单独保存 user 的来访记录，让角色知道 user 来过；这条来访与之后角色本人发出的操作分开归因。点赞、收藏、关注和“我的”按身份隔离，旧版顶层偏好继续归 user，角色偏好放入 `accounts[actor.key]`，不重标旧评论或历史作品。异步互动在发送时固定 actor，切换视角后完成／重试仍属于原身份。

点击右上角“＋”发布当前身份自己的作品，可选择分享给哪个角色世界。作品先保存，char／NPC 再按内容点赞、评论或互相接话；回复某条评论时保存具体回复对象，下一轮回应可继续该讨论。角色已经写下的评论不会再由 AI 以同一身份重复回应自己；其他角色可以接话或保持沉默。收藏属于各自身份的私人记录，不向其他人传播。

涉及 user 的转发通过持久化 outbox 写入相应角色的真实 user 私聊：user→char 为 user 发出的卡片，char→user 为该角色发来的卡片。角色之间的转发保存在视频号内部 `shares`，只给当事人记录可知事实，不伪造 user 的私聊。一同观看保存两位参与人的身份，每条消息保留 actor；角色邀请 user 时不能让 AI 代替 user 应答，user 切回自己的视角可以加入同一会话。角色之间的一起看不写入 user 的聊天记录。

“看看新作品”或聊天后的 Agent/JEV 会判断角色是否发布，也可以选择继续已有作品的公开评论和点赞；不强迫所有人围着用户发言，不替用户发布或回复。角色和 NPC 的发言身份、世界书来源及引用作品范围由程序验证。用户的来访、明确打开作品、点赞／取消、关注／取消、评论、共同观看及已送达转发写入视频号活动记录；普通聊天的 `buildSystemPrompt` 只接入当前角色实际知道的记录，即使当时没有主动发私聊，之后也能记得这些经历。可以自然提起或暂时不提，不要求每轮汇报。来访／打开记录半小时去重，活动保留最近 600 条，每次聊天读取当前角色最近 24 条及最近作品。

直播点击“看看谁开播”；发布仍由角色判断是否合适。进房后使用竖屏画面，顶部悬浮主播信息、底部输入和向上滚动的弹幕；选世界和更新按钮仅显示在列表。侧边可打开完整记录、剧情选项、点歌和画面选项；退出房间不等于要求主播收播，收播入口在画面选项内，完成后保留回顾与私聊。

直播画面按 A → B → C 顺序：A 复用设置页已保存的 Vivix API，创建一条 9:16 实时会话，RTC 首帧到达才标记为视频，聊天生成的主播台词／动作在同一会话继续执行；用户侧不采集麦克风和摄像头。两种媒体都已配置时优先 A，视频连接失败、断流或动作错误后关闭该视频会话，再进入 B。B 复用聊天生图路由（包括 NovelAI），依据主播参考图和当前剧情绘制竖屏场景；本机压缩并保存成功后展示，返回房间可复用已保存图片。在画面选项可主动按最新剧情更新图片，不随每条弹幕反复收费生图。没有媒体配置或 B 也失败时使用 C：主播头像、场景文字、动态声纹装饰和同一套滚动弹幕。声纹装饰不表示有真实音频。三档都保留点歌、弹幕、剧情选择及后续私聊，点歌本身不调用歌曲生成服务。

A 复用 Vivix 原生声音设置；默认静音播放，有原生音色时可点击开启声音。原视频设置选择 TTS 或静音时，本直播只播放静音画面并显示对白字幕，不擅自替换为另一音色。视频的密钥、RTC 凭据、控制令牌和临时播放句柄不写入直播状态或备份，参考图临时上传仍遵循现有 Vivix 转发约定。

刷新回应和切换主题保留同一个 RTC 节点，不重复创建会话；弹幕只播放真实已有消息，不编造观看人数，不循环伪造评论。每 1.6 秒展示下一条，旧消息向上移出；完整原文保留在记录。关闭直播页、切换应用、收播或页面卸载时清理连接；创建中的迟到会话仍须关闭，迟到生图不得回写旧房间。生图请求传入取消信号；图片／存储失败明确显示保底状态，不显示生成成功。界面遵循全部微信主题，包含像素灰字体与直角控件、恋爱透明玻璃浮层。

打开页面读取已有内容，不自动重新生成。用户点击更新可请求角色判断是否发布；聊天后的 Agent/JEV 也可选择性触发。拒绝／不确定的判断不发布，每个聊天轮次只尝试一次，并限制发布频率。

数据继续使用 `wechat_video_state`、`wechat_live_state`，纳入现有备份。旧作品和房间迁入新界面。每次网络互动先保存当前身份的事件，失败保留事件并显示重试。网络完成时重新读取状态，防止覆盖并发修改；同一事件仅请求一次，同一直播房间只允许一个未完成互动，失败后重试或撤销再继续。

私聊用持久化 outbox：先保存待发送内容，再向角色历史写入带 `discoverEventId` 的消息，角色保存成功后确认发送。确认失败后重试检查历史标记，不重复添加；角色保存失败撤回本次新增消息，保留待发送任务。删除／拉黑角色后停止生成及投递。

验收覆盖：旧数据保留；Agent/JEV 肯定／否定判断；角色与 NPC 身份；评论回复、点赞私聊、关注／收藏、一起看多轮与恢复；直播弹幕、点歌、选择、结束与回访；API／格式／存储失败、重试与并发去重；备份恢复。界面覆盖全部微信主题、320/375px 窄屏、47/59px 顶部安全区、底部安全区及运行中切换主题。

验证命令：`node --test tests/discover-story.test.cjs tests/vivix.test.cjs tests/chat-image-feedback.test.cjs`、`node scripts/check-discover-story-browser.cjs`、`node scripts/check-live-room-browser.cjs`、`node tests/run.cjs`。直播浏览器检查运行真实的 Vivix 适配器，使用模拟 REST／WebSocket／RTC 和生图响应，验证 A→B→C、未配置、图片缓存、保存失败、退出后迟到结果、连续弹幕、首帧与会话去重、11 主题及安全区；画面素材使用内置角色图作为 API 返回夹具，不代表真实付费生图／生视频的效果或连通结果，不消耗用户实际 API 配额。截图在 `artifacts/live-room/`，其余视频号验收在 `artifacts/discover-story/`。
