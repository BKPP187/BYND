# BYND 外部内容测试边界

## 产品约束

用户于 2026-10-20 明确：BYND 是付费产品，当前保留酒馆角色卡、预设等导入能力，是为了开发期方便测试。生态成熟后，需要把这类兼容功能与正式产品隔离。不能把当前的测试入口当作正式版长期公开功能，也不能据此把第三方卡片、预设或扩展内容作为付费产品素材分发。这是用户的产品边界，不是对所有第三方内容作统一法律判断。

当前继续保留测试入口，不提前关闭，也不在本次修改中实施完整的构建隔离。正式隔离时需要覆盖角色卡、预设、正则、世界书及相关恢复路径；入口、解析与运行适配应作为测试兼容层管理。BYND 自有格式、自有内容和第三方测试数据需分别管理。将来迁移或停用兼容层前，要保留用户数据并明确迁移路径。

## 当前读取能力

- 标准 `prompts` 与旧格式 `main_prompt` 可作为聊天提示词读取。
- `extensions` 是有内容的数据，不能因为缺少 `prompts` 就提示文件为空。
- 导入保留全部 `extensions`，包括 `regex_scripts`、`SPreset`、`entryGrouping` 与未知扩展字段，以纯文本方式展开查看。
- 外部导入记录标记 `importSource.purpose = testing` 并保留文件名；此标记仅用于来源识别，尚不是发布或授权控制。
- 扩展查看不等于酒馆助手运行兼容。当前不会把扩展 JSON/HTML 当成系统提示词，也不会自动写入全局正则或执行扩展脚本。只含扩展的导入保留当前聊天预设；同名覆盖正在启用的提示词记录时，清除该记录的启用状态，避免悬空引用。
- 同时含提示词和扩展的文件保留两类内容，已有聊天提示词流程继续工作。助手的具体加载入口及依赖需要对照用户的导入说明确认，不能仅凭扩展字段名称宣称完整兼容。

## 验证

`node --test tests/preset-import.test.cjs` 验证扩展完整保留、混合文件、活动预设、文本转义、旧空记录、读取和保存失败。

`node scripts/check-preset-import-browser.cjs` 验证导入、展开查看、编辑与刷新、320/375px 窄屏，以及父容器和顶栏分别承担 47/59px 安全区。可通过 `BYND_PRESET_DIR` 指向本机测试目录，原文件不会复制进仓库或打包。

## 无外部预设的默认聊天

默认创作规则由 BYND 自写，随应用代码提供，不读取或复制本机第三方预设内容。没有启用有效提示词时自动加入聊天的 system 消息；自定义预设有已启用的非空正文时优先使用它，全关、空记录和仅扩展配置继续使用默认规则。默认段落放在角色与世界观的压缩步骤后，避免被长设定截掉。群聊成员、气泡和动作协议沿用现有规则。

规则直接描述角色创作行为，区分虚构描写与赞同，减少因题材或情绪冲突造成的误拒，不把产品设置说明写给模型。当前实现属于默认创作与减少误拒的提示层，不能把它标为已经保证破限。请求注入测试和模拟接口检查只证明规则被发送，不证明任何真实模型一定接受某种题材；不修改上游模型策略或自动切换用户接口。
