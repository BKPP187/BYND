# 角色自主事件

入口：角色台 → 心意收件箱。桌面编辑的应用列表中也可添加「心意」。未读数量会显示在入口；新事件以轻提示出现，手绘事件附画作缩略图。来信要拆封才算已读。

## 触发与决策

`systems/character-events/events.js` 保存有效互动和最后活跃时间。有效互动只从**已保存成功**的角色快照中提取用户消息，群聊、NPC、欢迎语、系统消息、缺失或未来时间戳不计入。首次安装或首次升级建立活跃基线，不补发过去的思念。

页面重开、从后台返回或从往返缓存恢复时，离开时长达到设置值（默认 3 天，1–90 天可改）才记录待判断的环境快照。页面完全关闭时不会运行模型，也不会逐日补扣调用。每个角色、每段离开最多记录一次决策；阈值不选择体裁或剧情。新的有效互动会取消该角色过期的待判断任务。

Jev 已配置且开启 `autonomousEvent` 场景时，先选择沉默或载体。选择沉默直接结束；Jev 不可用或不确定时由现有聊天 API 的 Agent 判断。生成上下文包含人设、身份与用户关系、世界书、长期记忆、近期聊天、离开时长和现有载体。模型可选择不行动。

## 事件协议 v1

模型响应示例：

```json
{
  "version": 1,
  "action": "act",
  "events": [{
    "type": "letter",
    "charId": "existing-character-id",
    "title": "终于寄出去的信",
    "body": "信件正文"
  }]
}
```

沉默返回 `{"version":1,"action":"none","events":[]}`。一次最多一件事。应用分配事件编号、创建时间、未读状态和分发状态；模型不能指定可执行 HTML、脚本或修改程序。

| type | 呈现与分发 |
| --- | --- |
| message | 写入对应角色聊天，保留 eventId 用于幂等重试 |
| letter | 收件箱「来信」，信封与拆封信纸 |
| note / diary | 收件箱「手记」 |
| album | 角色生成图进入 BYND 相册，不混入用户拍摄照片 |
| notification | 收件箱与应用内新心意提示，不自动请求系统推送权限 |
| widget | 桌面未读留话，打开后消失；原文留在手记 |
| doodle | 手绘画作卡片与到达缩略图 |
| newspaper | 黑白私人小报 |
| bottle | 玻璃瓶内落下的短语，支持重播及减少动画设置 |

信件首次打开会连续播放约 6.7 秒的寄信前奏：黑丝带在米白纸上展开 → 短暂黑场 → 寄信日期 → 黑底白丝带与标题 → 黑色封蜡信封。日期来自事件生成时间，不虚构离线期间的写信日期。可以跳过前奏；前奏及信封展示不消费未读，拆封动画完成后才登记已读。已读信直接打开信纸，底部可以重播前奏。关闭或切换应用会取消动画计时器；系统减少动态效果设置会直接展示信封。

思念瓶使用细颈圆肩的透光轮廓，彩色短语逐个下落、轻弹并错落堆叠。短语按当前手机宽度及实际文字尺寸排布，最多 24 句长短语也不会被瓶身截掉；可以重播，减少动态效果时直接呈现完整堆叠。丝带和封蜡资源位于 `assets/character-events/`。

共同字段：title（1–100 字符）、body（1–8000 字符），可选 imageUrl（HTTPS 或 PNG/JPEG/WebP data URL）。`album` 和 `doodle` 可用 imagePrompt（最多 1800 字符）调用现有生图服务。生图失败不伪装成已完成图片。

`bottle.words`：1–24 个短语，每个最多 30 字符。`doodle.strokes`：最多 48 条折线，每条为 `{ "color":"#334455", "points":[[x,y],...] }`；2–80 个坐标点，范围 0–300。UI 只用经过校验的数值与颜色绘制 SVG，不执行模型传来的 SVG 源码。

新载体需同时加入 SLOTS、校验函数、提示词字段说明、分发处理及 UI；未实现的载体不会自动获得执行权限。

## 保存、失败与迁移

`bynd_character_events_v1` 是事件源记录，同时保存决策收据与待分发事件。只有先写入事件、再完成目标存储，才标记 delivered。聊天和相册写入失败会回滚本次新增项。目标已保存而收据失败时，使用 eventId 识别既有记录，重试不重复追加。

模型调用失败保留 pending 与具体原因，自动重试冷却 30 分钟；页面可见时每分钟检查待处理判断，从后台返回时也会检查，收件箱可手动重试。发送和生图失败保留原事件，重试不重新生成文字。并发任务串行处理，支持 Web Locks 的浏览器同时锁定跨标签页分发。关闭开关、删除角色、或新的有效互动发生后，迟到的模型决策不会创建事件。初始化遇到角色尚未加载或存储失败时，重新打开收件箱可再次初始化。生图期间导入或重新加载角色数据后，分发使用当前角色对象。

完整备份包含该键。心意导出文件为 `{version:1,events:[...]}`，导入时先验证全部记录，未知角色或损坏条目使整次导入失败，既有记录不受影响；相同 id 不覆盖，成功导入的待分发事件单独重试。存储损坏时不静默清空。

验证：`node --test tests/character-events.test.cjs`、`node scripts/check-character-events-browser.cjs`、`node tests/run.cjs`。专项测试覆盖初始化恢复、前台自动重试、生图中角色重新加载，以及聊天保存成功但分发收据写入失败后的去重。浏览器检查覆盖返回与切换应用、320/375px、47/59px 顶部安全区、父容器及顶栏两种预留方式、拆封未读状态、导出导入、保存失败、聊天重试去重，并通过真实角色保存函数验证互动登记和聊天/相册分发；完整备份中的手绘字符串也必须安全转义。使用合成数据和本地模型响应，不调用真实收费 API。
