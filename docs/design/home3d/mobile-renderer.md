# 小屋：Android 实时渲染预算

这次继续使用本地 Three.js r180 / WebGL2 实时房间，默认推进相机，减少常驻 UI，并建立移动端画质控制。房间和家具是真实几何。银发男生使用模型专属基础骨骼；兔耳蓝裙女生已生成网格，保留官方 23 关节绑定与测量关节位置。两个形象支持独立切换为已有立绘。切换 renderer 本身不能把图片变成立体人物。

## 构图与操作

房间采用正交相机，默认垂直世界跨度 6.7，横向跨度随手机屏幕比例变化。房间边缘允许裁切；不再根据房间包围盒缩小到全景。单指拖动平移，双指捏合、滚轮和按钮平滑缩放，范围 0.5–3.5 倍；复位回到近景默认构图。平移焦点受房间尺寸限制。

相机模块独立管理焦点、缩放、yaw/pitch 和阻尼；为未来手机旋转手势预留 `rotate` 接口。桌面 Alt 拖动可验证旋转，普通拖动始终平移。装修仍使用世界坐标射线拾取，保存的是家具世界位置，不是屏幕像素。

常驻 UI 为紧凑顶栏、视角按钮、角色状态胶囊和底部操作。共同生活天数、纪念数、详细状态放入点击角色后的面板；装修、陪伴、回忆、日常、设置全部保留。高度不超过 740px 时，房间切换收进左上角按钮弹出的面板。47/59px 顶部安全区分别验证父容器预留和顶栏预留，不叠加。

验收指标是 `(场景矩形面积 - 常驻场景内控件面积) / 扣除顶部原生安全区后的屏幕面积`，目标 75%–85%。这是留给世界的可交互区域，不把背景空白冒充家具面积；同时检查近景截图和相机裁切。

## 四档策略

| 目标帧率 | 30 | 60 | 60 | 根据设备选择起始档位 |
| DPR 上限 | 1.25 | 1.75 | 2.25 | 跟随当前档位 |
| 实际 framebuffer 像素上限 | 90 万 | 150 万 | 240 万 | 跟随当前档位 |
| 阴影尺寸 / 更新频率 | 512 / 10Hz | 1024 / 20Hz | 2048 / 30Hz | 动态调整 |
| 各向异性上限 | 2× | 4× | 8× | 同时受 GPU 上限约束 |
| 常规家具贴图长边上限 | 1K | 2K | 2K | 跟随当前档位 |
| 重要角色/近景资产上限 | 2K | 2K | 4K | 跟随当前档位 |
| 已解压贴图预算，含 mipmap | 64MiB | 128MiB | 192MiB | 跟随当前档位 |

| 每帧 draw call 审查预算 | 150 | 220 | 280 | 跟随当前档位 |
| 附加填充光 / 家具点光源 | 关闭 / 0 | 开启 / 最多 1 | 开启 / 最多 2 | 跟随当前档位 |
| 微尘粒子数量 | 0 | 6 | 12 | 跟随当前档位 |
| 全屏后处理 | 关闭 | 关闭 | 关闭 | 关闭 |

抗锯齿在创建 WebGL 上下文时请求硬件 MSAA；实际是否启用记录到 `runtime.stats().resolution.antialias`。PBR、ACES 色调映射和 sRGB 输出都在基础渲染中完成。当前不增加 bloom/SSAO 全屏 pass；以后增加后处理必须占用同一帧耗时与显存预算，而不能把它当免费提升。

实际 pixel ratio 为 `min(设备 DPR, 档位 DPR, sqrt(像素预算 / CSS面积), GPU支持的绘制尺寸 / CSS尺寸) × renderScale`。renderScale 在 0.8–1.0 内动态调整。Canvas 的真实宽高随宿主尺寸重建，CSS 只规定布局，不放大低分辨率图像。硬件上限同时考虑纹理、renderbuffer 和 viewport 尺寸。

## 自动降载与恢复

CPU 核数、可用的设备内存提示、最大纹理尺寸、省流量设置和可用的 GPU 名称只决定起始档位；未知设备默认均衡，软件渲染和明显弱设备从流畅开始。GPU 型号提示不等于性能承诺。

每 4 秒汇总实际帧间隔和 CPU 提交耗时；支持时使用非阻塞 GPU timer query。丢弃 disjoint 结果，不等待 GPU 完成。帧率持续低于目标的 82%，或 CPU/GPU 超过帧预算的 88%，先降低 renderScale，再降档；两次降载至少间隔 8 秒。稳定满足目标 94% 且 CPU/GPU 低于预算 65%，连续 6 个窗口且距上次变化至少 30 秒，才逐步恢复。

手动选择表示质量上限，也受持续卡顿保护；恢复不超过所选档位。自动恢复不超过设备起始档位。隐藏页面、房间加载和长时间暂停不计入性能判断；退出释放资源。上下文丢失显示重试入口，重新创建 renderer，不显示虚假的成功状态。

网页无法可靠读取所有 Android 手机的温度，以上机制以持续耗时作为降载依据。实际温升、功耗和 60FPS 验收必须在真机完成。

## 材质与资产规则

主家具以原生 2K 贴图为制作目标。BaseColor/Emissive 使用 sRGB；Normal/Roughness/Metalness/AO 使用非颜色数据空间。保留导入 GLB 的 PBR maps、粗糙度和金属度；原有纯色家具继续使用主题材质。缩小采样使用 mipmap，斜角表面采用受档位及硬件约束的 anisotropy。变更贴图尺寸前释放旧 GPU 分配，再上传新尺寸。

同一贴图按共享资源只计一次显存；不足时先降低普通资产，再降低重要资产，不放大原始低清图片。2K RGBA8 加 mipmap 约占 21.3MiB，一件家具若分别使用三张这种贴图就接近 64MiB，因此优先共享图集、合理合并 Roughness/Metalness/AO，并限制重要 4K 资产数量。纹理预算不包括 framebuffer、阴影、几何、驱动开销及保留的 CPU 原图，不代表整应用的总显存。

小装饰当前有两级真实几何 LOD，按屏幕投影尺寸选择；8/12px 阈值提供迟滞，避免闪烁。相机放大后恢复原始细节，不增加原始高档模型的三角面。导入家具和其他骨骼角色需要资产制作时提供 LOD；脸部独立 UV、足够纹素密度和准确五官比盲目增加整个身体的三角面更重要。远景依靠 mipmap、小装饰 LOD 和普通资产上限，不强制加载全部最高规格。

银发男生分别打包 2.5万/7万/18万 三角面的远/中/近景资源，色彩贴图长边 1K/2K/4K；近景辅助贴图不超过 1K。实际上传再受画质总预算限制，原始 8K 源只保留在制作目录。默认世界身高 1.55；近景进入/退出阈值 370/300 个 CSS 投影像素，中景 180/150；流畅最高使用中景网格。只保留当前角色网格，新档位就绪后释放旧网格、材质、贴图和 skeleton；失败保留当前档，关闭/换房后的过期结果直接释放。

运行时基础绑定只适用于这个已核对朝向/比例的男生模型，不是通用自动绑定工具。坐姿弯曲大腿和膝盖，并按坐垫高度及前缘放置骨盆；躺姿把头对齐床的 local -Z 枕头端。两个内置模型已接入跟随骨骼的闭眼材质表情，睡眠开启，醒来及 LOD 切换后恢复；眨眼、手指和衣服权重仍需精修。角色选择用轻量拾取体，避免手机每次点击遍历 18 万个变形三角面。

床铺分别提供躯干、枕头及脚部接触高度。角色保持单位缩放，用头部抬升和小幅髋关节弯曲贴合寝具；装饰靠枕避开睡眠位置。生成模型的靴子按三角面分离，躺下时隐藏靴子、显示连续脚形的薄袜，原靴子放在地板上；起身恢复，切换姿势重置所有关节位置和旋转。袜子是本地补建的基础脚部网格，不是源模型自带的精修裸足。

坐姿根据座位高度调整大腿倾角，避免固定 90 度导致双脚悬空。基础步态按移动速度使用小幅髋摆动、摆动腿屈膝及脚掌方向补偿，转向阻尼；仍非手工制作的完整行走动画。读书使用有封面、双页及书脊的独立 3D 道具，采样实际蒙皮手部网格跟随持握；走路时隐藏道具。书页和袜纹使用小尺寸本地纹理，随角色资源释放。

现有小型程序纹理保持原尺寸，不为凑“2K”插值放大。当前未配置 KTX2/Draco；以后引入压缩贴图需要相应加载器和压缩显存统计。超大原图的 CPU 解码内存仍需在资产制作和加载阶段控制。

三角面和 draw call 数是资产接入审查预算，通过 `runtime.stats()` 查看；当前不会为硬凑数字擅自删除用户家具。贴图预算通过尺寸降级执行；异常数量的资产即使缩到最小仍可能超预算，此类内容需在资产接入时拆分房间或共享材质。

## 验证与真机验收

自动检查覆盖 320/390/430px 宽、640/740/844px 高，DPR 3，47/59px 安全区，父容器/顶栏两种预留方式。验证实际 framebuffer 与 DOM 尺寸、默认裁切、双指缩放、平移、短屏切换房间、四档设置、失败写入保持旧设置、真实上传的 2K 纹理切换尺寸、上下文丢失重试和退出释放。

桌面软件 WebGL 的截图与帧率不能代替 Android GPU 测试。发布前选普通 Android、中高端 Android 各至少一台，均衡与自动连续运行 15 分钟：记录帧间隔 p50/p95、画质变化、GPU timer（可用时）、内存趋势和温升；覆盖近景脸部、家具斜角、持续移动/缩放、装修、房间切换、后台恢复和上下文丢失。中高端优先稳定 60FPS；普通设备允许自动降到稳定 30FPS；极致出现持续低帧率必须降载。

实现参考官方 [Three.js renderer](https://threejs.org/docs/pages/WebGLRenderer.html)、[Texture](https://threejs.org/docs/pages/Texture.html) 与 [MDN WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)。维护时以项目打包的 r180 API 为准。
