# 小屋近景与窗光调整

2026-10-17，本地版本 1.1.921。

按用户提供的两张参考图调整奶油白、浅木、百叶窗、亚麻帘和窗边植物。默认进入室内高度的透视近景，拖动观察房间；第一人称、第三人称、俯视和整栋查看继续保留。装修仍使用俯视相机。近景是独立场景能力，不依赖两个预设人物的外形或骨架；本次没有增加用户人物生成接口，也没有调用付费生成服务。

`apps/home3d/atmosphere.js` 创建可释放的窗边布景。静态零件按材质合批，叶片使用实例绘制，家具下的柔和接触阴影合为一次绘制。窗光使用羽化的地面投影，避免手机全屏后处理；它是风格化的光照近似。夜间压暗窗外和天花板、关闭白天地面光斑，室内保留暖色环境光。俯视时隐藏天花板。已有用户自定义布局与装修选择继续优先；游戏房默认相框挪到侧墙，避免盖住新增窗户。

## 性能处理

- 组件并行请求，保留经典脚本的注册顺序；备用立绘和设置预览按需加载。
- Android 继续使用原有 Base64 资源镜像，不改成加载已在 APK 中排除的原始 PNG，不增加重复打包。
- 人物与家具并行准备，家具解码仍限制为三个并发；失败或取消时释放并发加载的模型。
- 流畅档保持远景人物模型，避免近景镜头立即触发额外的中景资源下载。
- 最多缓存一份 2MiB 内的光脚原始字节；每个模型仍独立变形和释放。
- 每帧检查存档原始内容，只有变化时才重新解析；保存失败仍走原有错误路径。
- 静止时阴影刷新上限为 2Hz，走动、生活动作或装修移动时使用对应画质的刷新频率。

## 本机对照

使用同一浏览器、390×844 视口、DPR 2、自动流畅档和 SwiftShader 软件渲染。基线从 Git HEAD 读取原运行时文件后经同一测试服务器提供，没有修改或回退工作区。表中的调整后采样保存在 `artifacts/home3d-cozy/measured-20261017.json`；复验会覆盖 `report.json`，启动时间会受到系统文件缓存影响。

| 首次入屋资源解码字节 | 14,869,403 | 6,862,586 |

## 验证入口

- `node tests/run.cjs`：完整项目测试。
- `node scripts/check-home3d-cozy-browser.cjs`：真实渲染、默认近景、昼夜、12 组窄屏/安全区布局、设置预览、立绘失败后重试、并发人物失败后的释放与重试。
- `node scripts/check-home3d-cozy-browser.cjs --baseline`：从 HEAD 读取旧运行时做相同入口的对照采样。
- `node scripts/check-home3d-renderer-browser.cjs --check`：原画质、手势、姿态、释放和 WebGL 恢复检查。
- `node scripts/check-home3d-browser.cjs`：HTTP/file 页面与原生立绘流程。
- `node scripts/check-android-asset-dedup.cjs`：源资源与离线镜像一致性。

截图和采样保存在 `artifacts/home3d-cozy/`，原渲染器检查报告保存在 `artifacts/home3d-renderer/`。没有构建 APK、推送 Git 或发布线上版本。

最终全量测试 1391 项通过；近景浏览器检查、原渲染器检查、HTTP/file 检查、离线资源一致性检查均通过。窄屏覆盖 320/390/430px、47/59px 顶部安全区，以及父容器/顶栏各自预留两种归属。失败路径覆盖备用立绘下载失败与重试、并发人物读取失败后的资源释放、界面错误提示与重新进入。
