# 回归检查

在项目根目录运行 `node tests/run.cjs`。使用 Node.js 22 或更新版本，不需要安装 npm 依赖。这个入口先检查应用 JavaScript 语法，再自动发现所有 `*.test.cjs`。

目前覆盖：

- 角色数据的新旧副本选择、空列表、轻量索引、读取失败、保存队列、容量不足和完整备份导入导出。
- 缓存清理保留收藏、歌单、相册、配置、未知键以及用户导入的字体。
- 相机发送到指定角色，防重复点击、失败回滚、重试，以及相册只接收角色发来的生成图。
- 全部聊天主题中的富文本卡片和普通 Markdown 消息。
- 快速与慢速启动、加载动画开关、PWA/APK 不重复显示启动页、梦境流程，以及 iPhone 顶栏安全区。
- 状态接口区分限流和额度不足、遵守 Retry-After、不延长已有冷却期、请求合并与失败后的手动重试。
- 真实时间中的联系间隔、历史消息日期、后台消息与重试、状态快照时效，以及虚拟时间和缺失时间戳的边界。
- 角色小手机每轮用户发言且 AI 回复后仅同步一次，重复打开与页面刷新复用内容，失败后手动重试、请求去重和存储失败处理。
- 小手机照片保存完成后更新预览，保存失败恢复原图，连续编辑按序保存，损坏图片和切换角色不会破坏当前设置。

单元测试使用独立内存数据，不读取浏览器里的真实聊天。存储测试提取现有持久化段落并模拟故障；发布前还应使用独立浏览器上下文验证真实 IndexedDB、各主题排版和照片选择流程。

iPhone 布局需要检查 320px、390px 和 430px 宽度，以及 0px、47px、59px 顶部安全区。顶栏采用 `border-box` 时，高度和内边距都应包含安全区；父容器已经避开安全区时不要重复叠加。桌面模拟不能代替 iPhone Safari/PWA 实机验收。

Android 工作流调用相同测试入口。发布 APK 前必须使用当前工作树构建，核对安装包内资源与源码一致，并验证签名。
